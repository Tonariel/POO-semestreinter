alloues dynamiquement, des copies personnelles empruntees par les etudiants,

    * Library possede les originaux de son catalogue.
    * Student possede les copies personnelles qu'il emprunte.
- Eviter les copies superficielles de classes proprietaires de Book*.
- Livrer la structure Public/Private et un executable Windows .exe fonctionnel.
- Faire apparaitre True/False pour chaque test requis dans main.cpp.

TACHE 2 - IMPLEMENTER LE COMPTEUR STATIQUE ET LE CYCLE DE VIE DE BOOK
=======================================================================
Objectif : compter correctement TOUS les objets Book vivants, y compris
ceux crees par copie. Criteres : section B (21 points).

FICHIERS : Public/Book.h et Private/Book.cpp

A FAIRE DANS Book.h
1. Conserver les informations metier : title, author, status et BorrowedBy.
2. Ajouter un membre de classe static, par exemple :
      static int AliveCount;
   En general, garder le compteur prive pour proteger sa valeur.
3. Declarer un constructeur explicite prenant titre et auteur.
4. Declarer un constructeur par copie : Book(const Book& other).
5. Declarer un destructeur : ~Book().
6. Declarer une methode statique pour lire le compteur :
      static int GetAliveCount();
7. Examiner les operations d'affectation/deplacement : une affectation
   remplace les donnees d'un objet existant, sans creer un livre vivant
   supplementaire. Un constructeur de deplacement cree, lui, un nouvel
   objet vivant et doit aussi incrementer le compteur s'il est permis.

A FAIRE DANS Book.cpp
1. Definir UNE SEULE FOIS le membre statique :
      int Book::AliveCount = 0;
2. Dans le constructeur ordinaire : initialiser les champs, augmenter
   AliveCount, puis afficher '+ Construct [titre] (count=N)'.
3. Dans le constructeur par copie : copier les champs du livre source,
   augmenter AliveCount, puis afficher '+ Copy [titre] (count=N)'.
4. Dans le destructeur : diminuer AliveCount et afficher
   '- Destruct [titre] (count=N)'.
5. Dans GetAliveCount() : retourner la valeur du membre statique.
6. Si un constructeur sans argument ou par deplacement existe, appliquer
   la meme regle de comptage : chaque nouvel objet vivant ajoute 1.
7. Pour operator=, ne PAS incrementer le compteur : aucun nouvel objet
   n'est construit. En cas de besoin, definir correctement ces operateurs.

POINT DE VIGILANCE
Le compteur suit les objets vivants, pas le nombre d'emprunts ni le nombre
de pointeurs. Un new Book(source) doit declencher le constructeur par copie.
Un delete sur ce Book doit declencher une destruction.

VALIDATION
- Avant toute creation : compteur = 0.
- Apres creation de 6 originaux : compteur = 6.
- Apres copie d'un de ces livres : compteur = 7.
- Apres suppression de cette copie : compteur revient a 6.
- Aucun decrement supplementaire ni compteur negatif.

TACHE 3 - CREER LA CLASSE LIBRARY ET GERER LE CATALOGUE
=======================================================================
Objectif : une bibliotheque possede et detruit ses propres livres.
Criteres : section C (stockage, new et delete).

FICHIERS : Public/Library.h et Private/Library.cpp

A FAIRE DANS Library.h
1. Declarer la classe Library.
2. Ajouter un membre prive du type :
      std::vector<Book*> Catalog;
   Chaque Book* de ce vecteur represente un livre du catalogue alloue
   dynamiquement ET possede exclusivement par Library.
3. Declarer une methode pour ajouter un livre (exemple d'interface) :
      void AddBook(const std::string& title, const std::string& author);
4. Declarer une methode pour retrouver un livre, par titre ou indice :
      Book* FindBook(const std::string& title);
   Le pointeur retourne est un ACCES au livre ; l'appelant ne doit pas
   appeler delete dessus.
5. Declarer une methode pour afficher la liste des livres et leur statut.
6. Declarer le destructeur ~Library().

A FAIRE DANS Library.cpp
1. Dans AddBook(), construire chaque original avec new Book(...).
2. Stocker ce pointeur dans le vecteur Catalog.
3. Dans FindBook(), parcourir Catalog et retourner le pointeur correspondant,
   ou nullptr si le livre n'existe pas.
4. Dans l'affichage, ecrire titre, auteur et statut disponible/emprunte.
5. Dans ~Library(), afficher le nombre de livres du catalogue, puis :
      pour chaque Book* du vecteur : delete pointeur;
   A la fin, ne pas laisser de pointeur possede non libere.

POINT DE VIGILANCE
Ne jamais enregistrer dans Catalog l'adresse d'une variable locale Book
cree sur la pile : Library essaierait ensuite de faire delete sur une
adresse qui ne provient pas de new. Ne jamais appeler delete deux fois
sur la meme adresse.

VALIDATION
- Six appels a AddBook() => six objets Book vivants.
- Les six originaux restent disponibles au depart.
- La destruction de Library detruit exactement les six originaux.

TACHE 4 - GERER EXPLICITEMENT LA COPIE DE LIBRARY
=======================================================================
Objectif : eviter la double destruction et les copies superficielles.
Critere : section C, 'La copie de Library est geree' (6 points).

FICHIERS : Public/Library.h et Private/Library.cpp

PROBLEME A RESOUDRE
Si Library contient vector<Book*> et qu'une copie automatique est faite,
les deux Library possedent les MEMES adresses. Leurs destructeurs feront
delete sur les memes livres : comportement indefini / plantage possible.

SOLUTION RECOMMANDEE POUR UNE REMISE SOLIDE : COPIE PROFONDE
1. Declarer Library(const Library& other).
2. Dans ce constructeur, creer un nouveau Book pour chaque original :
      new Book(*livreDeOther)
   Le constructeur par copie de Book fait ainsi augmenter le compteur.
3. Declarer Library& operator=(const Library& other).
4. Pour l'affectation : gerer l'auto-affectation, puis remplacer proprement
   les livres possedes sans fuite memoire. Une technique de copie temporaire
   et echange (copy-and-swap) peut simplifier la gestion des erreurs.
5. Prevoir les operations de deplacement ou les interdire explicitement.
   Un deplacement valide transfere la propriete sans laisser les deux
   Library detruire les memes adresses.
6. Tester la copie d'une Library contenant 2 livres, puis la destruction
   de l'originale et de la copie : chaque objet ne doit etre detruit
   qu'une fois et le compteur doit revenir a sa valeur initiale.

ALTERNATIVE
Si la consigne exacte valide une classe non copiable, declarer les
operations de copie '= delete'. MAIS la grille attribue 6 points a la
gestion de la copie : la copie profonde est l'option la plus demonstrative.

POINT DE VIGILANCE
Eviter de deplacer/detruire un catalogue tant que des Student conservent
des references vers ses originaux. Dans main(), creer Library AVANT Student,
ainsi les etudiants seront detruits en premier a la sortie de portee.

VALIDATION
- Deux bibliotheques copiees n'ont pas les memes pointeurs Book*.
- Detruire l'une ne provoque pas de double delete dans l'autre.
- Le compteur inclut tous les livres de la copie et revient a l'equilibre.

TACHE 5 - ADAPTER STUDENT AUX COPIES PERSONNELLES SUR LE TAS
=======================================================================
Objectif : un etudiant emprunte sa PROPRE COPIE du livre du catalogue.
Criteres : copie personnelle, limite de cinq, retour et destruction.

FICHIERS : Public/Student.h et Private/Student.cpp

A FAIRE DANS Student.h
1. Ne plus representer les emprunts par un simple vector<string> : ce
   format ne contient aucun objet Book a detruire.
2. Prevoir un stockage des copies Book* possedees par l'etudiant.
   Une structure conseilee pour eviter l'ambiguite des titres :
      Loan { Book* CatalogBook; Book* PersonalCopy; }
   - CatalogBook : adresse non proprietaire de l'original.
   - PersonalCopy : copie possedee par Student, a detruire avec delete.
   Conserver les emprunts dans vector<Loan>.
3. Garder le constructeur Student et les methodes GetInfo(),
   BorrowBook(Book&) et ReturnBook(Book&).
4. Ajouter ~Student() pour detruire les copies personnelles restantes.
5. Ajouter une methode consultable pour le test de limite, par exemple :
      bool CanBorrow() const;
   et une methode indiquant le nombre d'emprunts (par exemple
   GetBorrowedCount()). Garder le champ CanBorrow_ ou calculer le droit
   d'emprunter directement avec la taille du vecteur.
6. Comme Student possede des pointeurs, gerer egalement la copie :
   copie profonde correctement implementee OU copie explicitement
   interdite (= delete). Interdire aussi le deplacement si non gere.
   La presence d'un ID_unique const impose un soin particulier pour '='.

A FAIRE DANS Student.cpp - EMPRUNT
1. Verifier que le nombre d'emprunts est strictement inferieur a cinq.
2. Verifier que le livre du catalogue est disponible.
3. Allouer la copie avec : new Book(BookToBorrow).
4. Enregistrer le lien entre original et copie dans les emprunts.
5. Marquer l'ORIGINAL du catalogue comme emprunte et preciser qui
   l'emprunte. Avec le code actuel, BorrowedBy stocke Name_ ; conserver
   cela si besoin, mais un identifiant unique est plus fiable.
6. Afficher la reussite et retourner true ; en cas de refus, retourner
   false SANS creer de Book et sans modifier le catalogue.

A FAIRE DANS Student.cpp - RETOUR
1. Rechercher l'emprunt correspondant a l'original indique (idealement
   par adresse CatalogBook, pas seulement par titre).
2. Si aucun emprunt correspondant : afficher un refus, retourner false.
3. Si l'emprunt existe : delete sur la copie personnelle UNIQUEMENT.
4. Supprimer l'entree du vecteur d'emprunts.
5. Remettre le livre ORIGINAL en statut Available et effacer BorrowedBy.
6. Le nombre d'emprunts peut repasser de cinq a quatre : un nouvel
   emprunt devient possible.

A FAIRE DANS Student.cpp - DESTRUCTEUR
1. Pour chaque emprunt restant, liberer la copie via delete.
2. Si un original doit etre remis disponible, s'assurer qu'il existe
   encore : cela suppose que Library vive plus longtemps que Student.
3. Ne jamais delete un Book* provenant du catalogue : il appartient
   exclusivement a Library.
4. Afficher les informations de Student sans modifier les objets.

POINTS DE VIGILANCE
- Le livre original reste dans Library durant tout l'emprunt.
- La copie personnelle est une adresse differente de l'original.
- Une creation de copie augmente le compteur ; son retour le diminue.
- La limite s'applique au nombre de copies personnelles en cours.
- Ne pas mettre Book par valeur dans le vecteur si le professeur attend
  explicitement des copies allouees sur le tas.

VALIDATION
- Premier emprunt de Dune : true, +1 livre vivant.
- Deuxieme etudiant sur Dune : false, aucun nouvel objet.
- Cinq emprunts simultanes : autorises.
- Sixieme emprunt : false, compteur inchange.
- Retour valide : true et -1 livre vivant.
- Retour d'un livre non emprunte : false, aucune suppression.
- Un nouvel emprunt apres un retour : true.

TACHE 7 - VERIFIER LA MEMOIRE ET LE CYCLE DE VIE
=======================================================================
Objectif : eviter une remise penalisable par une fuite ou un double delete.
Criteres : compteur final a 0 et absence de plantage.

A FAIRE
1. Compiler avec les avertissements : -Wall -Wextra -Wpedantic.
2. Verifier qu'il n'y a aucune erreur, et comprendre les avertissements.
3. Executer tous les tests de main.cpp et comparer au scenario attendu.
4. Verifier que chaque appel a new aboutit a UN delete effectif.
5. Verifier que Student ne detruit jamais les originaux de Library.
6. Verifier que Library ne detruit jamais les copies personnelles.
7. Verifier que toute copie de Library alloue de nouveaux Book distincts.
8. Verifier qu'apres la destruction d'une copie, le compteur baisse de 1.
9. Verifier que les refus d'emprunt ou de retour ne changent pas le compteur.
10. Tester l'auto-affectation/copie de Library si ces operations existent.
11. Tester la sortie de portee avec des emprunts non rendus : le
    destructeur de Student doit liberer les copies restantes.
12. Tester sur Linux avec AddressSanitizer si disponible, par exemple
    dans un build separe configure avec :
      cmake -S . -B build-asan \
        -DCMAKE_CXX_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer -g' \
        -DCMAKE_EXE_LINKER_FLAGS='-fsanitize=address,undefined'
      cmake --build build-asan
      ./build-asan/mon_programme
    Les outils peuvent necessiter des paquets installes sur la machine.
13. Si Valgrind est disponible :
      valgrind --leak-check=full ./build/mon_programme
    Chercher les fuites (definitely lost), acces invalides et doubles delete.

ERREURS A NE PAS LAISSER
- Double delete (deux proprietaires de la meme adresse).
- Suppression d'une adresse d'objet local (non alloue avec new).
- Destructeur absent pour une classe proprietaire de pointeurs.
- Copie superficielle de Library ou Student.
- Utilisation d'un Book* du catalogue apres destruction de Library.
- Compteur final different de 0.

VALIDATION
- Execution normale, sans plantage.
- Tests de refus vrais (sans effet secondaire).
- Compteur final 0.
- Aucun rapport d'erreur memoire pendant les essais disponibles.
